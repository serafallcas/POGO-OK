Repenser l'application comme une plateforme opérationnelle d'évaluation :
- parcours guidé ;
- arbres de décision par question ;
- validation indépendante ;
- génération contrôlée des findings ;
- plans d'action reliés à des findings validés ;
- reporting fiable ;
- traçabilité complète.

6. ARBRES DE DECISION

Tables :
- decision_trees
- decision_nodes
- decision_edges
- decision_outcomes

Types de nœuds :
- yes_no ;
- single_choice ;
- multi_choice ;
- numeric ;
- maturity_gate ;
- evidence_gate ;
- reviewer_gate ;
- outcome.

Arbre standard :
Q1. La pratique existe-t-elle ?
- Non : score 0 ou 1
- Oui : continuer

Q2. Est-elle documentée et approuvée ?
- Non : score maximum 2
- Oui : continuer

Q3. Est-elle déployée de manière homogène ?
- Non : score maximum 2
- Oui : continuer

Q4. Des preuves d'exécution sont-elles disponibles ?
- Non : score maximum 2
- Oui : continuer

Q5. La pratique est-elle mesurée par des KPI ?
- Non : score maximum 3
- Oui : continuer

Q6. Une amélioration continue est-elle démontrée ?
- Non : score maximum 4
- Oui : score potentiel 5

Règles :
- aucun score supérieur au plafond de l'arbre ;
- score 3 exige une preuve d'exécution ;
- score 4 exige un KPI ou une preuve de mesure ;
- score 5 exige amélioration continue ;
- N/A exige justification ;
- preuve obligatoire manquante bloque la validation.

9. WORKFLOW DE VALIDATION D'UNE REPONSE
Draft -> Completed by Evaluator -> Submitted for Review ->
Reviewed -> Correction Required ou Accepted -> Validated.

Blocages :
- score absent ;
- conclusion absente ;
- justification insuffisante ;
- preuve obligatoire manquante ;
- arbre incomplet ;
- score au-dessus du plafond ;
- N/A non justifié.

Le reviewer peut :
- accepter ;
- demander correction ;
- ajuster le score avec justification ;
- rejeter une preuve ;
- demander une preuve ;
- confirmer ou annuler le finding potentiel.

10. VALIDATION GLOBALE DE L'ASSESSMENT

GATE 1 - COMPLETENESS
- 100 % des questions obligatoires traitées ;
- réponses finalisées ;
- N/A justifiés ;
- preuves obligatoires présentes.

GATE 2 - QUALITY REVIEW
- reviewer assigné ;
- réponses critiques revues ;
- scores incohérents corrigés ;
- preuves invalides traitées ;
- commentaires clos.

GATE 3 - FINDINGS VALIDATION
- findings potentiels acceptés ou rejetés ;
- sévérité validée ;
- cause, impact, recommandation renseignés ;
- doublons fusionnés.

GATE 4 - ACTION PLAN VALIDATION
- chaque finding confirmé possède une action ;
- responsable, échéance, priorité et critères de clôture renseignés ;
- accord management enregistré.

GATE 5 - FINAL APPROVAL
- score recalculé ;
- dashboard à jour ;
- rapport généré ;
- approbateur final désigné ;
- approbation enregistrée.

Aucun assessment ne peut être clôturé si un gate est incomplet.

- score <= seuil ;
- alerte critique ;
- preuve obligatoire absente ;
- écart cible important ;
- non-conformité réglementaire ;
- contrôle critique non déployé ;
- faiblesse répétée ;
- décision reviewer.

Structure :
- criteria ;
- condition ;
- cause ;
- consequence ;
- risk_statement ;
- impact ;
- likelihood ;
- severity ;
- recommendation ;
- management_response ;
- owner ;
- target_date ;
- validation_status.

Rédaction :
Critère attendu -> Situation observée -> Cause -> Risque/impact -> Recommandation.

Déduplication :
- comparer titre, domaine, processus, cause et questions sources ;
- proposer fusion ;
- autoriser finding transversal ;
- conserver tous les liens sources.

Règles :
- aucune action sans finding validé ;
- aucune action sans owner ni échéance ;
- aucune fermeture sans preuve ;
- action en retard = alerte ;
- action critique = validation sponsor.
